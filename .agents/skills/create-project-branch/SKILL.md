# 프로젝트 작업 브랜치 생성

특정 서비스나 작업자별 경로 제한을 미리 가정하지 않고 사용자 요청과 실제 대상 경로를 기준으로 작업한다.

## 절차

1. 저장소 루트, `git status --short`, 현재 브랜치, remote와 추적 브랜치를 확인한다.
2. 작업 대상 경로를 식별하고 저장소 루트부터 해당 경로까지 적용되는 `AGENTS.md`와 루트 `.claude/rules/git-convention.md`를 완전히 읽는다. 규칙이 충돌하거나 대상 경로가 불명확하면 사용자에게 질문한다.
3. 미커밋 변경이 있으면 새 브랜치에 가져갈지가 요청에서 명확한지 확인한다. 불명확하면 생성 전에 질문하고 임의로 stash, reset, commit하지 않는다.
4. 이슈 번호가 있으면 `gh issue view <번호> --json title,labels`로 실재 여부와 유형을 확인한다.
5. base는 사용자가 지정한 값을 우선한다. 지정하지 않았으면 저장소 규칙, 기본 브랜치와 현재 추적 관계를 확인해 결정하며 근거가 둘 이상이면 질문한다.
6. 브랜치 이름은 사용자 지정 이름을 우선한다. 지정이 없으면 저장소 Git 규칙과 기존 사용례로 제안하며 `/codex` 또는 `codex/` 접두사를 강제하지 않는다.
7. `git fetch origin <base>` 후 `origin/<base>`에서 `git switch -c "<branch>" "origin/<base>"`를 실행한다. 같은 이름의 로컬 또는 원격 브랜치를 덮어쓰지 않는다.
8. 생성 결과는 `<branch> (브랜치)`, `<short-hash> (커밋)` 형식으로 보고한다.

push는 함께 요청받았을 때만 한다.
