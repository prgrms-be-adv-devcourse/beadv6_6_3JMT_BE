## 1. 한글 자동완성 — 자모·초성 (결정 D9)

한글은 타이핑 중간 상태가 있다: "프롬프트"를 치는 동안 입력창은
`프 → 프로 → 프롬 → 프롬ㅍ → 프롬프`로 변하고, `프롬ㅍ`은 글자 단위 prefix가 아니다.

```
자모 분해:  색인 "프롬프트" → ㅍㅡㄹㅗㅁㅍㅡㅌㅡ
           입력 "프롬ㅍ"   → ㅍㅡㄹㅗㅁㅍ      (분해하면 접두어 ✔)
초성 검색:  입력 "ㅍㄹㅍㅌ" → 초성 필드(ㅍㄹㅍㅌ)와 매칭 ✔
```

**구현: 자모/초성 변환은 앱 코드 전처리** (한글 플러그인들은 ES 9.x 미지원 — 방치 상태).

- 색인 시 앱이 `name` → 자모 문자열·초성 문자열을 생성해 별도 필드(`nameJamo`,
  `nameChosung`)에 저장. ES 쪽은 그 위에 **edge_ngram(1~20)** 분석기만 건다.
- 검색어도 서버에서 같은 Java 유틸로 분해해 match — 변환 로직이 한 곳(유닛 테스트 대상).
- 자모 변환은 유니코드 산수 몇 줄(음절 = 0xAC00 + 초성×588 + 중성×28 + 종성).
- 이 서브필드들은 **products-v1 매핑에 처음부터 포함** (Phase 2에서 리인덱스 없이 진행).

## 2. 제안 API — 3그룹 응답, 콜드스타트부터 단계적으로

`GET /api/v1/search/suggest?q=프롬ㅍ` → 최대 3그룹 병합 응답:

| 그룹 | 출처 | 가능 시점 |
|---|---|---|
| ① 상품명 | products의 `nameJamo/nameChosung` 매칭, 인기 가중 정렬(salesCount) | **콜드스타트부터** — Phase 2 |
| ② 인기 검색어 | behavior-logs의 SEARCH_EXECUTED를 1시간 배치로 집계(최근 7일 창) → 소형 `search-keywords` 인덱스 | Phase 3 |
| ③ 내 최근 검색어 | Redis (userId별 최근 검색 리스트 — 검색 히스토리 기능과 공유) | Phase 3 |

- 콜드스타트엔 ①만으로 시작 — 상품명 자체가 제안 사전이고 인기 가중으로 품질 확보.
- **응답 스키마를 처음부터 3그룹으로 고정** — ②③이 켜져도 FE 변경 없음.
- **자동완성 입력은 행동 로그로 남기지 않는다.** 로그는 실제 검색 실행 시에만 —
  인기 검색어 집계가 "프", "프로" 같은 타이핑 조각으로 오염되는 것을 방지.
- 자동완성엔 OpenAI·벡터가 전혀 관여하지 않음(순수 term 조회, 건당 수 ms).
  FE에 디바운스(입력 멈춤 200ms 후 요청)만 요청.

## 3. 오타 교정 — 결과가 빈약할 때만 사후 발동

모든 검색에 교정을 돌리면 멀쩡한 검색어도 건드린다. 결과 수 기준 발동:

```
검색 실행 → 결과 N건
  ├─ N ≥ 3      : 그대로 반환 (교정 없음)
  ├─ 0 < N < 3  : 결과 + "혹시 '프롬프트' 찾으셨나요?" 제안 링크 동봉
  └─ N = 0      : Term Suggester로 교정어 조회
       ├─ 있음 → 교정어로 자동 재검색 ("'프름프트' 대신 '프롬프트' 결과입니다" 표시)
       └─ 없음 → 빈 결과
```

- Term Suggester(name 필드, 편집거리 기반) + **collate로 "그 교정어가 실제 결과를
  내는지" ES가 검증**한 것만 노출 — 0건짜리 교정어 제안 방지.
- Phase 2 이후엔 semantic 레그가 웬만한 오타를 흡수하므로, 이 경로는
  "lexical 0건 + 시맨틱도 빈약"인 진짜 오타에서 주로 발동한다.

## 4. 기본값 (노브 등급은 문서 7)

- edge_ngram 길이 1~20 (등급 B — 매핑에 박힘)
- 제안 개수: 상품명 5 / 인기 검색어 5 / 최근 검색 3
- 인기 검색어: 최근 7일 창, 1시간 배치
- 오타 발동 임계: 3건 미만(제안) / 0건(자동 재검색)
