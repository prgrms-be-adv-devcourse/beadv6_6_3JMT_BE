# 검색·추천 관련성 하한과 통합 추천 후보 설계

작성일: 2026-08-14
관련 이슈: #745
기준 브랜치: `fix/#745-jina-reranker-threshold`

## 목적

검색, 상품 상세의 비슷한 상품, 회원 맞춤 추천에서 후보가 모두 무관하면 결과 개수를 억지로
채우지 않고 0건을 반환한다. PostgreSQL pgvector로 기준 상품마다 반복하던 추천 후보 조회는
Elasticsearch의 통합 후보 조회로 교체하고, Jina reranker는 최종 관련성 하한 필터로 사용한다.

## 배경

검색은 BM25와 벡터 검색으로 후보를 넓게 모아 RRF로 합친 뒤 Jina가 관련성을 다시 검증한다.
초기 Jina 하한 `0.5`는 실제 점수 분포보다 높아 직접 관련 상품까지 제거했다. 운영 입력과 같은
상품명·태그·설명·모델명 조합으로 측정한 결과 필수 관련 상품의 최저 점수는 `0.06910534`,
무관 상품의 최고 점수는 `-0.06565287`이었고 검색 하한을 `0.05`로 재보정했다.

반면 현재 상품 상세와 회원 추천은 PostgreSQL pgvector가 가까운 후보를 요청 개수만큼 반환한다.
회원 추천은 장바구니와 구매에서 기준 상품을 고른 뒤 기준마다 유사 상품 쿼리를 실행하고,
ai-service가 기준별 순위를 가중 병합한다. 관련 상품이 없어도 그나마 가까운 상품이 결과를
채울 수 있고, 기준 개수만큼 쿼리가 반복된다.

실측한 코사인 거리에서는 관련 상품과 무관 상품의 구간이 겹쳤다. 관련 상품이 `0.505`, `0.531`인
반면 무관 상품이 `0.483`, `0.488`, `0.489`인 사례가 있어 단일 pgvector 거리 하한으로 두 집합을
분리할 수 없다. 따라서 pgvector 하한 조정이 아니라 후보 수집과 최종 관련성 검증의 책임을
분리한다.

## 확정한 결정

### 1. 세 기능에 같은 관련성 원칙을 적용한다

- 검색, 상품 상세의 비슷한 상품, 회원 맞춤 추천 모두 후보가 전부 무관하면 0건을 반환한다.
- 후보 수집은 BM25와 벡터 검색이 담당한다.
- 최종 관련·무관 판정은 Jina 하한 필터가 담당한다.
- Jina는 추천 후보의 통과 여부만 판단하며 ES가 만든 순서를 바꾸지 않는다.
- 판매량·조회수·평점·신선도 같은 인기 가중치는 비슷한 상품과 회원 추천에 사용하지 않는다.

### 2. 상품 표현 규칙을 통일한다

BM25 기준 텍스트, 임베딩 원문, Jina query와 document는 같은 상품 표현을 사용한다.

| 상품 유형 | 사용하는 필드 |
| --- | --- |
| 공통 | 상품명, 태그, 설명 |
| `PROMPT` | 공통 필드 + 모델명 |
| `PROMPT` 이외 | 모델명 제외 |

본문 `content`와 첨부 파일 내용은 placeholder·예시 문구로 인한 오탐과 입력 크기 증가를 막기
위해 포함하지 않는다. 상품 유형은 하드 필터나 점수 가산 기준으로 사용하지 않는다. 내용이
관련되면 서로 다른 유형도 후보가 될 수 있다.

### 3. 같은 상품 유형 가산점을 제거한다

현재 비슷한 상품 정렬의 동일 유형 `0.05` 가산점은 제거한다. BM25·벡터·Jina가 실제 내용의
관련성을 판단하므로 유형 자체에 별도 점수를 더하지 않는다. 이로써 Jina 하한과 유형 가산점에
같은 숫자 `0.05`가 서로 다른 의미로 공존하는 혼동도 없앤다.

### 4. 상품 상세의 비슷한 상품을 하이브리드 후보 조회로 전환한다

```text
현재 상품 1개
→ 기존 상품 임베딩과 상품 표현 조회
→ ES에서 BM25 + kNN 후보 수집
→ 후보 병합
→ 자기 상품군 제외
→ Jina 하한 필터 1회
→ 통과 상품만 ES 순서로 반환
```

요청 개수만큼 결과를 채우지 않는다. Jina 하한을 통과한 상품이 없으면 빈 목록을 반환한다.

### 5. 회원 추천 후보를 ES 요청 한 번으로 통합한다

회원 추천 기준은 다음으로 제한한다.

- 최신 장바구니 상품 최대 10개
- 최신 구매 상품 최대 10개
- 중복 제거 후 최대 20개

활동 상품의 임베딩을 평균 내지 않는다. 서로 다른 관심사가 평균 벡터에서 희석되지 않도록 각
상품의 텍스트와 벡터를 독립 조건으로 유지하되 하나의 ES Search 요청에 함께 넣는다.

```text
최대 20개 활동 상품
→ 기존 임베딩 일괄 조회
→ ES Search 요청 1회
   ├─ 활동 상품별 BM25 조건
   ├─ 활동 상품별 kNN 조건
   ├─ 장바구니 신호 가중치 1.0
   └─ 구매 신호 가중치 0.7
→ 통합 후보 목록
→ Jina 하한 필터 1회
→ 이미 보유한 상품군 제외
→ 최종 limit 적용
```

한 ES 요청 안에서도 각 기준 벡터와 후보의 비교 연산은 필요하지만, 애플리케이션이 기준마다
PostgreSQL 또는 ES를 순차 호출하지 않는다. 여러 활동 조건에 함께 관련된 후보는 ES 점수가
누적되며, 한 관심사에 강하게 관련된 후보도 포함될 수 있다.

Jina query에는 장바구니와 구매 신호를 구분해 최대 20개 기준 상품의 표현을 넣고, documents에는
ES가 모은 통합 후보를 넣는다. Jina 점수는 임계값 통과 여부에만 사용하고 최종 순서는 장바구니와
구매 가중치를 반영한 ES 통합 순서를 유지한다.

### 6. 추천 패키지가 알고리즘과 정책을 소유한다

`recommendation` 패키지는 유지한다. 비슷한 상품과 회원 추천은 단순 검색 API가 아니라 기준 상품,
활동 신호, 가중치, 제외 대상과 노출 개수를 결정하는 추천 알고리즘이기 때문이다.

```text
recommendation
├─ 상품 상세 비슷한 상품 정책
└─ 회원 활동 기반 추천 정책

search application/infra
├─ ES 후보 검색 포트와 구현
├─ BM25·kNN 요청 구성
└─ Jina 외부 연동
```

추천 계층이 ES 클라이언트나 Jina HTTP 구현을 직접 알지 않도록 search가 제공하는 포트를 사용한다.
반대로 search가 장바구니·구매 가중치와 보유 상품 제외 같은 추천 정책을 소유하지 않는다.

### 7. PostgreSQL 임베딩은 원본으로 유지한다

없애는 것은 PostgreSQL의 실시간 유사 상품 조회 쿼리다. `product.embedding`은 상품 임베딩의
원본이며 ES 재색인과 복구에 필요하므로 유지한다.

상품 상세와 회원 추천을 모두 ES 후보 조회로 전환한 뒤 다음 기존 경로를 제거한다.

- 기준 상품별 PostgreSQL pgvector 유사 상품 조회
- 동일 유형 가산점 기반 정렬
- 회원 추천의 기준별 순위 응답
- ai-service의 기준별 Weighted Rank Fusion

## 실패와 경계 조건

- Jina API 키 미설정, timeout, 통신 오류 또는 비정상 응답이면 추천은 빈 목록을 반환한다. 추천에는
  검색의 BM25-only 폴백처럼 무관 상품 노출을 막을 수 있는 안전한 대체 검증기가 없기 때문이다.
- 일부 기준 상품에 임베딩이 없으면 해당 기준은 BM25 조건만 사용한다. 모든 기준이 무효면 0건이다.
- 기준 상품, 장바구니 상품, 구매 상품과 같은 상품군의 다른 버전은 추천하지 않는다.
- 판매 중이 아니거나 삭제됐거나 임베딩과 검색 문서가 모두 없는 상품은 벡터 후보에서 제외한다.
- ES에는 상품군의 현재 판매 대표 문서가 있으므로 과거 구매 버전 ID와 현재 문서 ID를 동일하다고
  가정하지 않는다. 활동 상품은 관심 기준으로 사용하고 제외 판단은 상품군 root ID로 수행한다.
- 활동 전체를 무제한으로 실시간 계산하지 않는다. 최신 장바구니 10개와 구매 10개라는 상한을 지켜
  오래된 관심사 희석과 ES·Jina 입력 증가를 제한한다.

## 추천용 Jina 하한

검색, 비슷한 상품과 회원 추천에 공통 하한 `0.05`를 적용한다. 세 기능 모두 Jina가 관련성 하한을
통과하지 못한 상품을 노출하지 않는다는 같은 정책을 사용한다.

운영 중 다음 평가셋으로 점수 분포를 계속 확인한다.

- 반드시 추천해야 하는 상품 쌍
- 추천을 허용할 수 있는 약한 관련 상품 쌍
- 반드시 제외해야 하는 무관 상품 쌍
- 서로 다른 상품 유형이지만 내용상 관련된 상품 쌍
- 여러 장바구니·구매 관심사를 함께 넣은 회원 추천 query와 후보

무관 후보의 최고 점수가 `0.05` 이상이거나 필수 관련 후보가 반복해서 하한 아래로 떨어지는 근거가
확보될 때만 검색과 추천의 설정 분리를 검토한다.

## 범위

### 포함

- 검색 Jina 하한 `0.5`에서 `0.05`로 재보정
- 상품 상세 비슷한 상품의 ES 하이브리드 후보 + Jina 필터 전환
- 회원 추천의 최신 장바구니 10개·구매 10개 통합 ES 후보 조회와 순서별 최신성 감쇠
- 회원 추천 Jina 단일 필터 호출
- 검색·비슷한 상품·회원 추천에 공통 Jina 하한 `0.05` 적용
- product-service와 ai-service 사이의 통합 추천 gRPC 계약 변경
- 기존 PostgreSQL 실시간 유사 상품 조회와 기준별 순위 병합 제거

### 제외

- 사용자 전체 활동 이력을 미리 집계하는 장기 취향 프로필
- 평균 임베딩 또는 사용자별 임베딩 저장
- 행동 로그 신규 수집
- 인기순 가중치 적용
- Jina 점수를 이용한 최종 재정렬
- 첨부 파일 본문 추출

## 검증 기준

### 상품 상세

- 직접 관련 상품은 Jina 하한을 통과해 노출된다.
- 상품 유형이 달라도 내용상 관련되면 노출될 수 있다.
- 무관 후보만 있으면 0건을 반환한다.
- 자기 상품군의 다른 버전은 노출하지 않는다.

### 회원 추천

- 장바구니와 구매 상품이 각각 10개를 초과해도 최신 10개씩만 기준으로 사용한다.
- 최대 20개 기준을 한 번의 ES Search 요청과 한 번의 Jina 요청으로 처리한다.
- 장바구니 `1.0`, 구매 `0.7`을 시작값으로 순서마다 `0.05`씩 낮춘 가중치가 ES 통합 순서에 반영된다.
- 이미 장바구니에 있거나 구매한 상품군은 최종 결과에서 제외된다.
- 통과 후보가 최종 limit보다 적으면 있는 만큼만 반환하고 0건도 허용한다.
- Jina 실패 시 관련성 검증 전 후보를 노출하지 않고 빈 목록을 반환한다.

### 회귀

- 일반 검색은 BM25 + kNN + RRF + Jina 흐름과 검색 정렬 계약을 유지한다.
- 상품 등록·수정 시 PostgreSQL 임베딩 저장과 ES 색인·재대사 흐름을 유지한다.
- PROMPT만 모델명을 상품 표현에 포함하고 다른 상품 유형은 모델명을 사용하지 않는다.
- product-service와 ai-service의 변경된 gRPC 계약을 양쪽 단위·통합 테스트로 검증한다.
