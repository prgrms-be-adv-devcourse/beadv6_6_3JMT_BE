# AI 정산 챗봇 발표용 아키텍처 디자인

## 목적

셀러가 정산 질문을 보낸 뒤 AI 답변을 실시간으로 받기까지의 구조를 16:9 발표 화면 한 장으로 설명한다.
서비스 구성만 나열하지 않고, 이 챗봇의 핵심인 비동기 Run과 반복 Tool Calling을 함께 드러낸다.

## 코드 근거

- Gateway가 `/api/v2/ai/settlement/**` 요청의 JWT와 역할을 검증하고 `X-User-Id`를 주입한다.
- AI Service는 질문을 동기 처리하지 않고 `202 Accepted`와 `runId`를 반환한다.
- 대화와 Run 상태는 Redis DB 1에 24시간 저장한다.
- Run Executor가 Agent를 백그라운드에서 실행하며 전체 제한 시간은 90초다.
- Spring AI Agent는 OpenAI 응답의 `tool_calls`를 확인한다.
- Tool이 필요하면 Guard가 서버 문맥의 `actorId`와 `runId`를 검증·주입한다.
- User Service gRPC는 PostgreSQL에서 해당 셀러 범위의 정산 집계만 반환한다.
- Tool 결과를 모델 문맥에 추가하고 최대 4라운드까지 다시 추론한다.
- Tool 호출이 더 없으면 최종 답변 정책을 검증하고 Redis Pub/Sub과 SSE로 응답한다.

근거 문서는 `docs/api-spec/ai.md`이며, 구현은 `ai-service/src/main/java/com/prompthub/ai/settlement/**`에 있다.

## 승인된 화면 구성

### 상단: 요청·실행 흐름

왼쪽에서 오른쪽으로 다음 다섯 단계를 배치한다.

1. **셀러 질문 접수** — 질문 POST, `runId`로 SSE 연결
2. **인증·라우팅** — JWT·Role 검증, `X-User-Id` 주입
3. **비동기 Run 생성** — Redis에 대화·Run 저장, `202 + runId` 반환
4. **백그라운드 실행** — 동시 실행 제한, 진행 상태 이벤트 발행
5. **Agent 시작** — 시스템 Prompt, 대화 이력, 질문을 모델에 전달

각 단계는 큰 번호, 담당 컴포넌트 태그, 제목, 최대 두 줄의 설명으로 구성한다.

### 하단: Agent 내부 Tool Calling

상단의 05 Agent를 확대해 다음 흐름을 왼쪽에서 오른쪽으로 표현한다.

1. **OpenAI 모델 추론**
   - 현재 문맥만으로 답변할 수 있는지 판단한다.
   - 추가 데이터가 필요하면 사용할 읽기 Tool을 선택한다.
2. **Tool 검증·실행**
   - ToolExecutionGuard가 `actorId`와 `runId`를 서버 문맥에서 주입한다.
   - 모델 인자에 seller ID를 받지 않는다.
3. **User gRPC 조회**
   - User Service가 PostgreSQL에서 셀러 본인 범위 집계를 조회한다.
4. **결과를 문맥에 추가**
   - Tool 결과를 대화 문맥에 넣어 OpenAI 모델을 다시 호출한다.

4번에서 1번으로 돌아가는 보라색 재추론 화살표를 배치하고 `최대 4회`라고 표시한다.
모델이 `tool_calls`를 반환하지 않으면 루프 아래로 빠져 최종 답변 생성·정책 검증을 수행한다.
이후 Redis terminal 상태 저장과 SSE `progress`, `delta`, `done` 전달로 이어진다.

## 화살표 규칙

- 같은 행의 순차 흐름은 카드 세로 중앙을 잇는 수평 화살표로 통일한다.
- 05 Agent와 하단 확대 영역은 짧은 수직 화살표로 연결한다.
- 재추론은 `06-D → 06-A` 한 개의 보라색 되돌림 경로만 사용한다.
- 재추론 화살표의 시작과 끝을 다른 카드나 설명선과 겹치지 않게 둔다.
- `tool_calls 없음` 분기는 06-A 아래에서 최종 답변 영역으로 빠진다.
- 최종 답변에서 Redis·SSE로 향하는 화살표는 별도의 직선으로 표시한다.
- 선이 카드 내부 텍스트, 섹션 제목, 다른 선을 통과하지 않게 한다.

## 시각 스타일

- 발표 비율은 16:9다.
- 배경은 흰색, 섹션 배경은 옅은 회색으로 유지한다.
- 기본 흐름은 파란색, Tool 실행은 보라색, 내부 데이터 조회는 초록색, 문맥 재주입은 주황색으로 구분한다.
- 본문보다 단계 번호와 제목의 대비를 높인다.
- 한 카드의 설명은 두 줄을 넘기지 않는다.
- 상단에 읽는 순서를 안내하고, 하단에는 보안·데이터 경계만 짧게 남긴다.

## 발표 핵심 메시지

1. API 요청과 AI 실행을 분리해 `202 + runId`와 SSE로 비동기 응답한다.
2. 모델이 임의의 셀러를 조회하지 못하도록 서버가 사용자 범위를 강제한다.
3. 모델은 Tool 결과를 문맥에 추가해 필요한 만큼 다시 추론한다.
4. OpenAI에는 원본 이벤트가 아니라 셀러 본인의 집계 결과만 전달한다.

## 완료 기준

- 16:9 화면에서 축소해도 모든 단계 제목을 읽을 수 있다.
- 발표자가 상단 01~05와 하단 06-A~06-D 순서로 설명할 수 있다.
- `모델 추론 → Tool 실행 → gRPC 조회 → 결과 재주입 → 모델 재추론`이 화살표만 보고도 이해된다.
- Tool 미호출 경로와 SSE 최종 응답 경로가 다른 선과 겹치지 않는다.
- 구현과 다른 컴포넌트나 데이터 흐름을 포함하지 않는다.
