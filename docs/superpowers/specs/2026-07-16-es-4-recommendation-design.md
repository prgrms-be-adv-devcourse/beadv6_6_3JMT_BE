# ES 검색·추천 설계 4 — 비슷한 상품·개인화 추천

> 전체 그림·결정 로그는 [0 — 개요](2026-07-16-es-0-overview-design.md) 참고.
> 이 문서의 로직은 전부 recommendation 패키지 소유 (경계는 문서 6).
>
> ⚠️ **대체됨 (2026-07-27)** — 세 가지가 바뀌었다.
>
> 1. **비슷한 상품 kNN을 ES가 아니라 Postgres(pgvector)에서 조회한다**(D12). 자기 family
>    제외·ON_SALE 필터가 실제 컬럼 조건이 되고, 색인 지연·ES 장애와 무관해진다. 폴백 이중
>    경로도 불필요해졌다
> 2. **컨트롤러 이관을 하지 않는다**(D11). `recommendation` 패키지는 신설하되 컨트롤러는
>    두지 않고, 엔드포인트는 `ProductController`가 계속 소유한다
> 3. **재정렬이 가중합에서 타입 보너스 1개로** 줄었다. `코사인유사도 + (같은 productType이면
>    0.05)`. `log1p(salesCount)` 항은 스케일이 무계라 가중치의 근거·해석이 없어 제외했다
>
> **개인화 홈 추천(문서 후반부)은 진행하지 않는다** — 행동 데이터 없이는 콜드스타트 폴백으로만
> 동작한다. 취향 벡터·다양성 규칙·콜드스타트 사다리 설계는 재개 시 참조용으로 유효하다.
> 상세: [2026-07-26 설계 변경](2026-07-26-search-recommendation-api-ownership-design.md)

## 1. 비슷한 상품 (상세 페이지)

기존 `GET /api/v1/products/{id}/related`의 **URL·응답 계약은 유지**, 구현만
recommendation 패키지의 ES 기반으로 교체 (Phase 2).

```
현재 상품의 저장된 embedding 사용 (OpenAI 호출 없음)
  → kNN 후보 20개 (자기 family 제외)
  → 앱 재정렬: 같은 productType +가산, log1p(salesCount) +가산
  → 상위 N 반환
```

- **크로스타입 허용.** "정산 자동화 프롬프트"와 "정산 엑셀 템플릿"은 실제 연관 상품.
  주제(벡터)가 1차 기준, 같은 타입은 가산점만 — 타입으로 자르면 상품 적은 초기에
  추천 칸이 빈다.
- **콜드스타트 무풍지대**: 임베딩은 색인 때 생기므로 행동 데이터 0이어도
  등록 직후부터 동작 — 벡터 방식의 최대 장점.
- 폴백: Phase 1(임베딩 없음)·ES 장애 시 기존 RDB 로직(같은 타입/태그) 유지.

## 2. 개인화 추천 (홈)

**취향 벡터**: 사용자가 행동한 상품들의 임베딩 가중 평균 = "이 사람 취향의 좌표".

```
취향 벡터 = 가중평균( 구매 ×3, 클릭 ×1 )      // 찜 ×2는 조건부 — 문서 5 D8
            (오래된 행동일수록 감쇠 — 반감기 14일)
```

- recommendation의 **프로필 배치(6시간)**가 behavior-logs를 읽어 유저별
  취향 벡터 + 선호 태그/타입 상위 목록을 계산, 소형 `user-profiles` 인덱스에 저장.

```jsonc
// user-profiles (1 shard / 0 replica), _id = userId
{ "tasteVector":  "dense_vector(1536, index:false)",  // 조회용 — kNN 색인 불필요
  "topTags":      "keyword",                          // 선호 태그 상위 N
  "topTypes":     "keyword",
  "behaviorCount": "integer",                         // 콜드스타트 임계 판정용
  "updatedAt":    "date" }
```

```
GET /api/v1/recommendations/home   (Gateway 헤더 X-User-Id 기준)
  ├─ 프로필 없음/행동 3건 미만 → 인기순 폴백
  └─ 프로필 있음 → ES 쿼리 한 방:
       bool {
         should: [ knn(취향 벡터, k=50),              // 의미적으로 취향 근처
                   terms(tags = 선호 태그, boost) ],   // 명시적 취향 가산
         filter: [ 이미 구매한 상품 제외 ]
       } + 인기 function_score 약하게
     → 앱에서 다양성 규칙 → 반환
```

### 실시간 반영 — "방금 본 것" 혼합

취향 벡터는 배치지만, **세션의 최근 조회 상품 3개**는 Redis에 실시간 적재
(행동 로그 컨슈머가 기록). 추천 시점에 그 상품들의 저장된 임베딩을 ES에서 꺼내
평균 내고:

```
최종 쿼리 벡터 = 배치 취향 벡터 × 0.7 + 최근 조회 평균 벡터 × 0.3
```

무거운 계산은 배치에, 즉각성은 벡터 산수 한 줄에.

### 다양성

점수순으로 뽑되 규칙 2개 — **같은 셀러 최대 2개, 같은 productType 연속 3개 금지**.
(후보 간 벡터 유사도로 밀어내는 MMR은 규칙 2개로 체감 효과 대부분이 나와 채택 안 함 — YAGNI.)

### 비로그인

user-profiles 없이 인기순 + (있으면) 세션 최근 조회 벡터 기반.

## 3. 콜드스타트 사다리 (전체)

```
서비스 오픈 직후(로그 0) : 인기순(카운트+신선도) + 비슷한상품(벡터, 이미 동작)
행동 1~2건              : 인기순 + 최근 조회 벡터 혼합
행동 3건 이상           : 취향 벡터 개인화 (인기 가산은 약하게 유지)
```

프로필 배치 6시간 · 세션 혼합비 0.3 · 셀러 캡 2 · 타입 연속 제한 3 ·
